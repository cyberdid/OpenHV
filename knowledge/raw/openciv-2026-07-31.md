# Source Record: RyanGrieb/OpenCiv, second inspection

- Repository: https://github.com/RyanGrieb/OpenCiv
- Inspected commit: `113eb908ffda2f50ff5c0d5a4a0bbe697904293a`
- Commit date: 2025-12-08
- Retrieved: 2026-07-31
- License: MIT
- Language/runtime: TypeScript, Node.js, browser client

The repository has not moved since the 2026-07-29 inspection: the same commit
is still `HEAD`, seven months later. This second pass measured what the server
actually executes rather than what its files are named, because the first
record described several systems as "incomplete" that turn out not to exist.

Scale: 15 TypeScript files, 3,623 lines, in `server/src`.

## What is implemented

**Map generation** — `map/GameMap.ts`, 1,139 lines, and the substantial piece
of the project. Land is painted by walking random circle paths from random
seeds until a target land mass is reached; isolated single ocean tiles are
filled; height comes from counting how often a tile was painted over, with the
highest 3% becoming mountains and 10-25% hills; biomes are assigned from a
temperature gradient that favours cold at the poles; rivers are traced with a
cached backtracking search; resources are placed from rules.

**Data-driven tables** — `config/tiles.yml` (173 lines) gives per-terrain
yields, `config/map_resources.yml` (185) gives per-resource spawn terrain, path
length, placement chance and a temperature band, `config/civilizations.yml`
(189) gives names, city lists, start biases and descriptive text.

**Unit movement** — pathfinding with movement carried across turns.

**Turn advance** — a counter and a timer.

## What is not implemented

| System | State at this commit |
|---|---|
| Population growth | `population = 1` in the constructor and never written again |
| Food | `foodSurplus = 0`, never written; consumption is computed and discarded |
| Research | no occurrences of `tech` or `research` in the server source |
| Diplomacy | no occurrences |
| Combat | no occurrences of `combat` or `damage`; `attackType` is a string carried for display |
| Trade | no occurrences |
| Government | no occurrences |
| Religion | no occurrences |
| Morale | present in the stat line as a literal `0` with a `TODO` |
| Buildings | `buildings.yml` contains one entry, Palace |

The city stat line sums building and worked-tile yields into science, gold,
production, faith, culture and food. Nothing consumes any of them. `incrementTurn`
raises a counter, resets the timer, notifies clients and fires a `nextTurn`
event whose only listener in the entire server is `Unit`.

So the turn loop advances a number and moves units. There is no economy, and
the civilisation simulation the project is named for has not been written.

## Against the layer already in OpenHV

| | OpenCiv | OpenHV `CivilizationState` |
|---|---|---|
| Population | fixed at 1 | children/adults/elders, workforce, employed, mobilized, migration pressure |
| Economy | yields summed, never spent | food, materials, energy with production, demand, storage and per-settlement stocks |
| Research | absent | 5 nodes with prerequisites, costs, per-profile priorities and real production effects |
| Diplomacy | absent | state, two-sided grievance, trust, war exhaustion, peace cooldown, reason codes |
| Trade | absent | routes with distance, capacity, risk and per-resource flows both ways |
| Crises | absent | stability, prosperity, collapse thresholds |
| Fields recorded per player | — | 65, plus 44 per settlement, 13 per diplomatic relation, 20 per trade route |

Every one of those OpenHV fields is synchronized, enters the state hash, and is
measured across a 112-match matrix.

## What is worth taking

The map generator, and only the map generator. Its land-mass painting, the
paint-overlap height trick, the temperature-gradient biomes and the
data-driven resource placement rules are real, self-contained work, and
OpenHV's own `RandomMapGenerator.cs` is 328 lines by comparison.

The yield tables are worth reading as a reference for what a terrain table
looks like, not for their numbers, which assume a hex Civ-5 economy.

## What this settles

Decision 0003 chose to model living factions natively rather than merge
OpenCiv, on the grounds that its codebase was "not a compatible or complete
engine layer". That judgement was correct and this inspection strengthens it:
adopting OpenCiv as the strategic layer would mean replacing a measured
simulation with a turn counter.
